# 融合版 1.3.1：真机反馈后的排版修正

用户提供的 1.3.0 iPhone 桌面截图显示：小号、中号余额与部分排行文字过小，内容挤在上半部，AI 条和页脚之间留白过多；大号长模型名称与 Neurons 数值间隔不足，排名后仍有较大空白。用户另附的 HTML 是概念稿，不能代表原生排版已经达标。此前桌面无重叠检查不足以发现原生文字压缩问题。

## 代码修正

- 只修改融合 Widget 的展示约束，保留主数字 28pt、圆环、数据含义及系统主题适配。
- 余额正文 11pt，排行 10.5pt，分别保留数值列及 14pt 行高；数值缩放下限为 90%，长名称采用单行省略。小号 AI 摘要缩放下限 85%。主数字为容纳长数值仍可单独缩放，不影响正文。
- 使用官方 fixedSize 的 vertical 约束保护文字自然行高，horizontal 保持 false，让长名称仍可按列宽省略。离线检查合约仅补入官方该属性，不冒充手机同步的完整类型声明。
- 去掉融合布局末尾的垂直 Spacer。小号、中号按 148/158pt 高度分配摘要、AI 条与页脚；大号按 329/354pt 高度及实际排名行数分配趋势图空间，页脚前保持 2–5pt 的设计间距。
- AI 模型列表省略 Cloudflare/provider 路径前缀，完整模型 ID 和精确统计仍可在管理页查看。超长小号用量和排行数值使用紧凑缩写；不修改统计值或缓存。
- 原 Workers、AI 两个独立版及融合查询、认证、缓存、UTC 统计均未修改。

## 实际检查

- npm run check：依据官方文档整理的合约类型检查。
- npm test：86 项逻辑和入口回归；新增检查余额/排行不能缩成小字、名称与数值独立列、三尺寸高度分配及页脚无需弹性空白。
- Browser：5 场景 × 320/390/1280 三种页面宽度 × 默认字体/Courier New 加 1.5px 字距，共 30 组、180 个三尺寸深浅色卡片。检查数字字形与圆环、数字截断、正文缩小到 9pt 以下、行内列间距、页脚间距及边界；最终未发现这些检查所定义的问题，页脚前间距约 2–5pt。宽字体是额外压力检查，仍不等同于 SwiftUI 排版。
- 新增 device-case 场景：通用 Worker 名称、三个 Worker、一个长名称模型、AI 仅一天有效记录。没有上传用户原截图、账号或凭据。数据来自桌面模拟，不进入 iPhone 包。
- 安装包保留原项目名、参数和 Keychain 作用域；13 个白名单文件。发布时校验 ZIP CRC、每份源码、版本与公开下载包 SHA-256。

读取官方 Skill 的 Widget/验证说明，核对本地官方 Fixed Size、frame、Text、HStack/VStack 与 Widget.displaySize 文档。[官方文档索引](https://scriptingapp.github.io/llms.txt) 列出了对应 fixedSize、frame 和 Text API。

## 尚需真机复验

更新原脚本到 1.3.1，关闭旧管理页并重新运行；监控项目选第一项融合版，分别进入三尺寸官方预览，重新加载后在桌面确认：

1. 余额及中号 TOP 3 保持可读字号，没有被缩成小字。
2. 大号长模型名可省略，Neurons 数值在自己的列中，两者之间留有间距。
3. 小号/中号 AI 条到页脚留白收敛；大号图表、排名和页脚均未重叠或溢出。
4. 深浅色、95% 告警、付费套餐及缺失历史继续正确显示。AI 只有 1/7 天有效数据时仍保留六天空缺，不伪造为零；0.6% 进度仍按真实比例绘制。

Windows 端没有 iOS 运行时或连接的 iPhone。本次修订后的原生结果尚未验证；所有新增 HTML/PNG 仅为实际 TSX 视图树的浏览器参考。
